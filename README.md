# TG Content Hub

Полуавтоматическое наполнение двух Telegram-каналов: чтение источников через
отдельный пользовательский аккаунт (Telethon), оценка и рерайт через OpenRouter,
ручное ревью владельцем, публикация через Bot API. Без ручного одобрения ничего
не публикуется.

## Стек

Python 3.12 · PostgreSQL 16 · Redis 7 · FastAPI · aiogram 3 · Telethon · Docker Compose

## Среда

Единственная среда разработки и продакшена — VPS (Ubuntu, Docker Compose).
Домашний ПК — только редактор кода и точка `git push`.
Сервер маломощный (1 vCPU / 1 GiB RAM / 10 GiB): включён своп 2G, лимит логов
контейнеров, после пересборок выполняется `docker image prune -f`.

## Быстрый старт

```bash
cp .env.example .env    # заполнить секреты
make up                 # первая сборка на 1 CPU — несколько минут, это норма
make health             # {"status":"ok","postgres":"ok","redis":"ok"}
make logs
```

## Сервисы

|Сервис|Назначение|Этап|
|---|---|---|
|postgres|состояние и аудит|0|
|redis|очереди, локи, счётчики предохранителей|0|
|migrate|применение миграций alembic (one-shot)|0|
|reader|чтение источников (заглушка)|1|
|pipeline|предфильтр → классификация → рерайт → карточка ревью (заглушка)|2–3|
|bot|ревью в Telegram (заглушка)|4|
|scheduler|очередь/расписание публикаций (заглушка)|5|
|api|веб-админка, `/healthz`|6|

## Доступ к админке (вариант А)

Порт `8000` привязан только к `127.0.0.1` на сервере. В интернет ничего не публикуется: бот, чтение и публикация работают исходящими соединениями. Доступ с домашнего ПК — туннель в сохранённой сессии PuTTY: Connection → SSH → Tunnels → Source port `8000`, Destination `127.0.0.1:8000`, Add, переподключиться. Затем в браузере: `http://localhost:8000/healthz`.

## Миграции

- Применить: `make migrate`
- Новая (после изменения моделей): `make revision m="описание"`

## Предохранители (задействуются в Этапе 3)

- `MAX_LLM_BUDGET_USD_PER_DAY` — пауза пайплайна до следующего дня при превышении; посты не теряются, ждут в очереди. Счётчик ведётся в Redis по данным `llm_calls`.
- `MAX_CANDIDATES_PER_DAY` — потолок карточек ревью в день.
- Оба значения, как и модели, переопределяются без рестарта через `app_settings` (в админке — этап 6).

## Эксплуатация на малом сервере

```
df -h                 # диск: том медиа и образы не должны распухать
free -h               # память и своп
docker image prune -f # после каждой пересборки образа
docker system df      # сводка по месту
```

## Дорожная карта

- Этап 0 — каркас: compose, конфиги, модели данных, миграция 0001, заглушки сервисов, `/healthz`
- Этап 1 — Source Reader (Telethon): тестовый + внешний источник, медиа, бэкфил
- Этап 2 — дедупликация и предфильтр
- Этап 3 — LLM-пайплайн (классификация, рерайт, версии, лог вызовов, предохранители)
- Этап 4 — ревью-бот: карточка, действия, правка ИИ, редактор
- Этап 5 — публикация: сейчас/очередь/расписание, лимиты, ретраи, идемпотентность
- Этап 6 — админка: настройки, источники, стили, очередь, статистика, аудит
- Этап 7 — приёмочные тесты по ТЗ §14, далее Mini App
